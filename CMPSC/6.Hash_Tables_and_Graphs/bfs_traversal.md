## 问题与直觉 / Problem and Intuition

从起点出发，先把所有“一步能到”的节点看完，再看“两步能到”的，再看“三步”的——像石子落水的波纹一层层扩散。要保证“先发现的先处理”，就用先进先出的队列（queue）。

Starting from a source, visit everything one step away, then two steps, then three, like ripples spreading on water. A first-in, first-out queue guarantees that nodes discovered earlier are processed earlier.

## 算法 / Algorithm

1. 起点入队，并标记为已发现。  
   Enqueue the start node and mark it discovered.
2. 队列非空时，出队一个节点 $u$。  
   While the queue is not empty, dequeue a node $u$.
3. 按规定顺序检查 $u$ 的每个邻居 $v$：若 $v$ 未被发现，标记、入队，并记录树边 $(u,v)$。  
   Check each neighbor $v$ of $u$ in the given order; if $v$ is undiscovered, mark it, enqueue it, and record tree edge $(u,v)$.

- **入队时就标记**，而不是出队时。否则同一节点会被多个邻居重复入队。  
  **Mark on enqueue,** not on dequeue; otherwise a node can be enqueued by several neighbors.
- 无权图中，BFS 树给出从起点到每个节点的最少边数路径。  
  In an unweighted graph, the BFS tree gives paths with the fewest edges from the start.
- 用邻接表时时间复杂度为 $O(V+E)$，前提是“是否已发现”能 $O(1)$ 判断（例如用集合）。  
  With adjacency lists the running time is $O(V+E)$, provided the discovered check is $O(1)$, for example with a set.

## 完整例题：`CMPSC/mod6.py` / Worked Example: `CMPSC/mod6.py`

仓库中的 `Graph.bfs` 使用有向邻接表，邻居按字母序（`sorted`）访问：

The repository's `Graph.bfs` uses a directed adjacency list and visits neighbors in sorted order:

```python
g1 = {'B': ['E', 'C'], 'F': [], 'C': ['F'],
      'A': ['D', 'B'], 'D': ['C'], 'E': ['F']}
Graph(g1).bfs('A')   # ['A', 'B', 'D', 'C', 'E', 'F']
```

| 出队 / Dequeue | 排序后的邻居 / Sorted neighbors | 新发现 / Newly discovered | 队列（队首在左）/ Queue (front left) |
| --- | --- | --- | --- |
| — | — | A | A |
| A | B, D | B, D | B, D |
| B | C, E | C, E | D, C, E |
| D | C | 无（C 已发现）/ none | C, E |
| C | F | F | E, F |
| E | F | 无（F 已发现）/ none | F |
| F | — | 无 / none | 空 / empty |

访问顺序为 `A, B, D, C, E, F`，与 doctest 一致。注意 D 排在 C 之前：D 在第一层（A 的邻居），C 在第二层。

The visit order matches the doctest. D precedes C because D is on level one, while C is on level two.

代码细节：`Queue.enqueue` 用 `insert(0, item)`，每次是 $O(n)$；`visited` 是列表，`nb not in visited` 也是 $O(n)$。课程练习规模下没有影响；规模大时可以改用 `collections.deque` 和 `set`。

Code detail: `insert(0, item)` and membership tests on a list are both $O(n)$. That is fine at exercise scale; larger graphs would use `collections.deque` and a `set`.

## 易错点 / Common Mistakes

- 出队时才标记已访问，导致重复入队或画出多余的树边。  
  Marking on dequeue, which causes duplicate enqueues or extra tree edges.
- 把 BFS 写成栈：栈得到的是深度优先顺序。  
  Using a stack, which gives depth-first order.
- 忽略题目规定的邻居顺序（如字母序）：不同顺序会得到不同但都合法的 BFS 序列。  
  Ignoring the required neighbor order; different orders give different valid BFS sequences.
